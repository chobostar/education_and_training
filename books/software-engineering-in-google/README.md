# Конспект: "Делай как в Google. Разработка программного обеспечения"

## Основная идея книги

Программная инженерия отличается от простого программирования тремя ключевыми аспектами:
- **Время** - код должен быть устойчивым к изменениям в течение всего жизненного цикла
- **Масштаб** - решения должны масштабироваться с ростом команды и организации
- **Компромиссы** - необходимо принимать обоснованные решения на основе данных

## Ключевые принципы

### Три столпа социального взаимодействия (HRT)
1. **Смирение (Humility)** - осознание того, что вы не центр вселенной и открыты к самосовершенствованию
2. **Уважение (Respect)** - искренняя забота о коллегах и признание их способностей
3. **Доверие (Trust)** - вера в компетентность других и готовность передать им управление

### Программная инженерия vs Программирование

**Программирование** = создание кода для решения текущих проблем

**Программная инженерия** = программирование, интегрированное во времени + учет:
- Долгосрочной перспективы развития
- Масштабирования команды
- Управления изменениями
- Поддержки кода десятилетиями

## Культура команды

### Миф о гениальности
- Великие продукты создаются командами, а не отдельными гениями
- Важность коллективной работы над индивидуальными достижениями
- Необходимость психологической безопасности для инноваций

### Почему сокрытие кода вредно:
1. **Раннее выявление ошибок** - чем раньше получена обратная связь, тем дешевле исправление
2. **Фактор автобуса** - знания должны быть распределены между участниками
3. **Темп развития** - командная работа ускоряет прогресс

## Обмен знаниями

### Создание среды обучения
- **Психологическая безопасность** - основа для признания незнания
- **Наставничество** - формальное и неформальное
- **Культура вопросов** - поощрение любопытства

### Масштабирование знаний
1. **Индивидуальные знания** → **Коллективные знания** → **Документированные знания**
2. Использование различных каналов:
    - Групповые чаты для быстрых вопросов
    - Списки рассылки для сложных тем
    - Системы Q&A (YAQS) для структурированного поиска
    - Документация для справочной информации

### Программа "Readability" (Удобочитаемость)
- Стандартизированный процесс наставничества через код-ревью
- Распространение лучших практик программирования
- Обеспечение консистентности кода во всей организации

## Инженерия равенства

### Проблемы предвзятости
- Бессознательные предубеждения влияют на разработку продуктов
- Необходимость разнообразия команд для создания инклюзивных продуктов
- Важность тестирования на недопредставленных группах пользователей

### Принципы инклюзивности
1. Создавать **со всеми**, а не **для всех**
2. Учитывать самых уязвимых пользователей при проектировании
3. Не строить предположений о справедливости - измерять её
4. Бросать вызов устоявшимся процессам

## Лидерство

### От разработчика к лидеру

**Роли:**
- **Технический лидер (TL)** - отвечает за техническую архитектуру и решения
- **Менеджер** - отвечает за людей, процессы и бизнес-результаты
- **Технический менеджер (TLM)** - совмещает обе роли в небольших командах

### Лидерство как служение
- Цель лидера - служить команде, а не управлять ею
- Создание атмосферы смирения, уважения и доверия
- Устранение препятствий и обеспечение ресурсов для команды

### Антипаттерны лидерства:
1. **Найм слабых специалистов** для укрепления своих позиций
2. **Игнорирование неэффективных сотрудников** ("надежда - не стратегия")
3. **Игнорирование личных проблем** команды
4. **Желание быть другом для всех** вместо эффективного лидера
5. **Компромиссы в найме** под давлением сроков

### Положительные паттерны:
1. **Забыть про эго** - доверять команде и признавать ошибки
2. **Быть мастером дзен** - сохранять спокойствие и задавать правильные вопросы
3. **Быть катализатором** - способствовать достижению консенсуса
4. **Устранять препятствия** для продуктивности команды
5. **Быть учителем и наставником**
6. **Ставить четкие цели** и приоритеты
7. **Быть честным** - не лгать, но объяснять ограничения
8. **Следить за удовлетворенностью** команды

## Масштабируемое лидерство

### Три "всегда" лидерства:

#### 1. Всегда принимайте решение
- Снимайте "шоры" и видьте более широкую картину
- Выявляйте компромиссы между различными вариантами
- Принимайте итеративные решения, не стремясь к идеальности

#### 2. Всегда уходите
- Создавайте самодостаточные команды, которые могут работать без вас
- Избегайте становления единой точкой отказа
- Распределяйте задачи и делегируйте подзадачи лидерам

#### 3. Всегда масштабируйтесь
- Оптимизируйте для направления, а не детального контроля
- Защищайте важные решения, но делегируйте менее критичные
- Определяйте политики вместо решения каждой задачи лично
